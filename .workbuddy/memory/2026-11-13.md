
## Genius 释义在「ノ/の」写法差异下落空（已修）

- 现象：`丸ノ内サディスティック`（Spotify 的写法）在 Genius 上是 `丸の内サディスティック`，两种写法搜索结果不互通。旧逻辑第一条查询只能命中 EXPO 版/Remix（0 注释），chooseRecording 接受后就不再找，面板显示「Genius 没有简介或注释」。
- 修法（`PlatformRecordingMatcher` / `SongMeaningService`）：
  1. `searchQueries` 增加「ノ→の」变体查询（在原始写法之后、裸标题之前）。
  2. `squashed()` 里把片假名折叠成平假名（保留 ー ヽ ヾ），`丸ノ内` 与 `丸の内` 相似度=1。
  3. 一条查询的命中不再终局：页面为空就继续试后面的查询，取第一个有内容的页面。
  4. 空结果不写缓存；缓存键加 `v2|` 前缀，旧缓存（含空结果）不再命中。
- 验证：`tests/run_platform_live_check.py` 实网命中 3943844，8 条注释；回归 80 项、边界 51 项。
- 提交 `262e1a8`，APK `build/ivLyrics-LSPatch-Spotify_Lyrics_Enhanced-r15.apk`。

## 释义面板：高度改由内容决定 + 左右滑动切 tab（已修）

- 病根：`PopupWindow` 固定高度 + `showAtLocation(Gravity.BOTTOM)`，显示后再 `setHeight()` 只改高度不改原点，卡片被顶到屏幕下方；所以切到「逐句歌词」（内容实测 10102px）时还是原来那一小截。
- 改法（`BaseLyricsActivity`）：
  1. 窗口改 `WRAP_CONTENT`，高度落在 `meaningScrollView` 的 LayoutParams 上 → 从底边向上长，不再需要重定位。
  2. 上限 80%→85%，下限 280dp→160dp。
  3. `MeaningScrollView` 重写 `onInterceptTouchEvent`：横向位移 >48dp 且明显大于纵向时抢手势，左滑=逐句歌词、右滑=歌曲简介，两端夹紧；卡片点击不受影响。
- 真机验证（丸ノ内サディスティック）：简介 900px → 左滑逐句 2217px → 右滑回 900px。

## 释义面板第四轮：单条隔离 / 谷歌 429 / 失败可见（已修）

- 我上一版把单卡点击写进了全局开关，导致点一张全部卡片跟着变。现在每条有独立「固定」状态（original/translation 两个 Set），点一张时先把其他条目按当前显示冻结，再翻转被点的那条；顶部胶囊仍是整页开关，用了会清空这些固定。
- 视觉状态由 `meaningItemShowsTranslated(key, resolved)` 统一判断，不再依赖全局标志。
- 谷歌 429：请求原来没有 UA/Referer。现加浏览器 UA + `Referer: translate.google.com`，429 时睡 1.2s 重试一次；仍失败则由另一个免密钥引擎顶上，并在面板里标注「已改用 X」。
- 失败不再无声：红色横幅写明引擎 + 原因（如 `Google Translate request failed (429)`），点横幅直接打开引擎列表。
- 教训：全屏 PopupWindow 打开时，再点灯泡/页面空白 = 点遮罩 → 关闭面板；盲测时别连点。
